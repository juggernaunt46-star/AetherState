FastAPI route introspection, SQLite, pytest, Ruff, scoped mypy, Node-based UI smokes, GitHub Actions

## Global Constraints

- No existing player-facing or functional behavior may be removed, hidden, weakened, renamed away,
  support-narrowed, or made less reachable.
- The preservation baseline is cumulative: public 1.24.0, the actual merge target, every completed
  hardening stage, and every working surface added while the program is underway.
- A discovered omission is added to the manifest. Omission or absent proof never authorizes removal.
- A proven defect is recorded as a defect; it is not frozen as intended behavior. Repair cannot
  remove its surrounding working surface.
- Stage 1 changes only `docs/hardening`, `docs/superpowers/plans`, `tests`, `tools`, and
  `.github/workflows/ci.yml`. It does not modify `src/aetherstate`, `st-extension`, corpus content,
  launchers, installers, configuration behavior, databases, routes, or player UI.
- The clean integration branch also contains cherry-picked, byte-exact copies of the two already
  approved `docs/superpowers/specs` contracts. Stage 1 does not author or revise those files.
- The dirty personal checkout is not an implementation surface. Work only in the isolated worktree.
- Do not read a personal database, personal config, personal session, prompt, story, credential,
  provider response, or personal path as test input. Historical schema fixtures contain DDL only.
- Public API paths, response keys and types, operation JSON, journal meaning, replay, card formats,
  configuration keys, supported Python/OS lanes, and byte-transparent non-gated streaming remain
  compatible.
- Existing fail-open and fail-closed boundaries remain as they are. Stage 1 observes them; it does
  not redesign them.
- New reports and fixtures are content-free. They may contain stable IDs, relative repository paths,
  commit/tree hashes, schema DDL, test-gate names, versions, durations, and safe error codes. They
  may not contain prose, prompts, request/response bodies, credentials, raw exceptions, or absolute
  personal paths.
- Verification is proportional:
  - change-loop target: 10 minutes or less;
  - substage target: 20 minutes or less, with `TEST_BUDGET_HOLD` before 45 minutes;
  - Stage 1 terminal local target: 45 minutes or less, with `TEST_BUDGET_HOLD` before the unapproved
    90-minute serial boundary;
  - one local full pytest run occurs at the Stage 1 terminal gate, not after every task;
  - Linux, Windows, Python, package, and JavaScript CI lanes run independently and in parallel;
  - unchanged evidence is reused by proof-input fingerprint;
  - only evidence dependent on a changed prerequisite is revoked and rerun.
- A test-budget hold triggers sharding, removal of duplicate proof, or explicit scope/timing
  direction. It never silently skips a required gate.
- No blind live-turn quota is part of Stage 1. No personal or model-backed live playtest is needed.
- Do not push, publish, merge, release, or replace a public tree as part of this plan.
- The implementation branch must have public-safe ancestry. It may contain cherry-picked copies of
  the two canonical design documents and this plan, but must not contain the private ancestry of the
  personal `main`.

## Terminal Artifact and Status Contract

The generated terminal artifact is:

```text
build/hardening/stage-1-terminal-report.json
```

`build/` is already ignored. The report is generated on the candidate under test, uploaded by CI,
and copied into the later integrated worktree when Stage 2 validates its prerequisite. It is not
committed, so it can record the exact evidence commit without a self-referential commit hash.

The report status is exactly one of:

- `PASS`: every required Stage 1 gate passed for the recorded proof-input fingerprint and manifest.
- `HOLD`: a correctness, coverage, compatibility, or historical-support requirement is unresolved.
- `TEST_BUDGET_HOLD`: required proof would cross the declared verification budget and must be
  optimized or repartitioned before continuation.
- `INVALID`: the report is malformed or stale, its evidence commit is not an ancestor, its proof
  inputs or manifest changed, or a required gate is absent.

Only `PASS` authorizes Stage 2 runtime work. `HOLD` and `TEST_BUDGET_HOLD` do not authorize a feature,
support narrowing, reduced proof, or a weaker Semantic Cube scope.

The exact consumer command is:

```powershell
$AetherPython = Join-Path $PWD 'build\stage1-venv\Scripts\python.exe'
$env:PYTHONPATH = "$PWD\src"
& $AetherPython tools/validate_stage_gate.py `
  --report build/hardening/stage-1-terminal-report.json `
  --stage stage-1-safety-baseline `
  --candidate HEAD `
  --require-pass
```

Expected after a valid Stage 1 integration: exit 0 and `PASS stage-1-safety-baseline` followed by
the report's 40-character evidence commit.

The report's proof-input fingerprint includes every tracked path and Git object byte except the
single later-owned file
`docs/superpowers/plans/2026-07-24-semantic-cube-narrator-output-integrity.md`. In particular, it
includes this Stage 1 plan, the umbrella design, the canonical Semantic Cube design, ordinary
documentation, every fixture, every test, every tool, and the workflow. The report also records and
validates the two design-document SHA-256 values above. This permits exact reuse after only the
canonical Stage 2 implementation-plan file is added; any other tracked change invalidates the
report. The evidence commit and evidence tree must still match the candidate or an ancestor exactly
as defined in Task 6.

This report is immutable Stage 2 **start authority**, not a terminal verdict on a repaired Stage 2
candidate. Before the first repair, Stage 2 may write audit receipts only under ignored
`build/hardening/semantic-cube/**`; it may not commit its tracked matrix or evidence files. Validate
Stage 1 PASS against the exact unchanged Stage 2 Task-1 base immediately before authoring the first
failing regression and runtime repair. That validation consumes Stage 1 start authority. Once Stage
2 changes any tracked proof input, do not regenerate or relabel Stage 1 PASS: Stage 1's
`no-runtime-diff` gate would correctly fail. Tracked Cube matrix/evidence commits follow the repair
transaction, or the final no-runtime audit when no repair exists. Stage 2 then owns cumulative
manifest proof, affected-cell proof, and its own terminal report for the changed candidate. In that
same first tracked transaction, Stage 2 replaces the bootstrap `stage-1-report` CI enforcement with
canonical job `stage-2-cumulative`, changes the owner marker to `stage-2-cumulative`, and removes
the Stage 1 `no-runtime-diff` marker. It does not keep running Stage 1 no-runtime proof against an
intentionally repaired candidate.

### 1.1 Write the failing manifest contract

- [ ] Create `tests/test_behavior_surface_manifest.py` with these exact invariants:

```python
from __future__ import annotations

import json
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]
MANIFEST = ROOT / "docs/hardening/post-1.24/behavior-player-surface-manifest.json"
BASELINE_IDS = ROOT / "tests/fixtures/hardening/behavior-surface-ids-1.24.0.txt"


def _load() -> dict:
    return json.loads(MANIFEST.read_text(encoding="utf-8"))


def test_manifest_is_cumulative_and_bound_to_public_124() -> None:
    value = _load()
    assert value["schema"] == "aetherstate-behavior-player-surface/1"
    assert value["baseline"]["version"] == "1.24.0"
    assert value["baseline"]["commit"] == (
        "82b58277d7a1fb167434be0290d3dfd2bb3588e2"
    )
    assert value["merge_target"] == value["baseline"]["commit"]
    assert value["cumulative"] is True
    ids = [entry["id"] for entry in value["surfaces"]]
    assert ids == sorted(ids)
    assert len(ids) == len(set(ids))


def test_public_124_surface_ids_can_only_be_preserved_or_extended() -> None:
    current = {entry["id"] for entry in _load()["surfaces"]}
    baseline = {
        line.strip()
        for line in BASELINE_IDS.read_text(encoding="utf-8").splitlines()
        if line.strip()
    }
    assert baseline <= current


def test_every_surface_has_resolvable_automated_proof() -> None:
    for entry in _load()["surfaces"]:
        assert entry["preservation"] == "required"
        assert entry["default_reachability"] in {"direct", "configured", "background"}
        assert entry["proofs"]
        for proof in entry["proofs"]:
            assert proof["kind"] in {"pytest", "node", "workflow"}
            if proof["kind"] == "pytest":
                assert "::test_" in proof["selector"]
                assert (ROOT / proof["selector"].split("::", 1)[0]).is_file()
            elif proof["kind"] == "node":
                assert proof["command"][:1] == ["node"]
                assert (ROOT / proof["command"][1]).is_file()
            else:
                assert proof["gate"]
```
